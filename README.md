# 🧊 인성이네 냉장고

냉장실·냉동실 재료를 2열로 한눈에 보고, 소비기한이 임박한 것부터 챙기고, 지금 있는 재료로 바로 되는 **아침·저녁 간단 식단**까지 보는 **모바일 전용 조회 화면**이에요.

👉 https://jongheeyi-crypto.github.io/fridge/

- 📱 폰에서 열어 홈 화면에 추가하면 앱처럼 써요.
- 👀 **보기 전용** — 로그인도, 입력도 없어요. 링크만 있으면 누구나 같은 화면을 봅니다.
- 🔒 이름·전화번호·집 주소 같은 개인정보는 넣지 않아요. 식재료와 식단만 담습니다.
- 📅 **없는 소비기한은 지어내지 않아요.** 날짜를 모르는 재료는 그냥 `냉장 보관` / `냉동 보관` 배지로만 표시됩니다.

## 화면 구성

| 탭 | 내용 |
| --- | --- |
| 🏠 전체 보기 | 요약 배지 + 오늘의 아침·저녁 추천 + 냉장실 + 냉동실 (모두 2열 그리드) |
| ❄️ 냉장실 | 냉장 재료 |
| 🧊 냉동실 | 냉동 재료 |
| 🍳 간단 식단 | 점심 식단 연동 배너 + 🌅 아침 추천 / 🌙 저녁 추천 |
| 🛒 장보기 | 떨어져 가는 것 / 필요한 것 |

재료 검색과 카테고리 필터(밀키트 / 생선·고기 / 유제품·빵 / 채소·과일 / 아이 맞춤)를 쓸 수 있어요.

## 데이터는 `data.json` 한 곳에서만 고칩니다

`index.html`·`styles.css`·`app.js`는 화면만 담당하고, 내용은 전부 `data.json`에 있어요.

```jsonc
{
  "isSample": false,                          // 예시 데이터면 true → 화면 위에 안내 배너가 뜸
  "updatedAt": "2026-11-15T17:02:00+09:00",   // 화면 상단 "마지막 업데이트" (KST)

  "fridge": [                                 // ❄️ 냉장실
    {
      "name": "[일미어담] 고등어구이 200g",
      "emoji": "🐟",
      "qty": "1개",
      "category": "생선·고기",                 // 필터에 쓰는 이름
      "expiryDate": null,                     // YYYY-MM-DD. 모르면 반드시 null
      "memo": "에어프라이어 6분 · 가시 주의"    // 선택
    }
  ],

  "freezer": [ /* 🧊 냉동실 — 같은 형식 */ ],

  "meals": [                                  // 🍳 간단 식단
    {
      "title": "우유 식빵 & 사과 모닝",
      "emoji": "🍞",
      "mealTime": "아침",                     // "아침" | "저녁"
      "who": "👶 인성이·온가족",               // 👶 인성이 추천 / 👨‍👩‍👦 온가족 / 🌶️ 어른용 등
      "time": "5분",
      "difficulty": "★☆☆ 초간단",
      "uses": ["우유 식빵", "감홍 사과", "전용목장우유"],  // 재료 이름이면 ✅ (부분 일치도 인정)
      "keywords": ["빵", "사과", "우유"],       // 이 메뉴에 들어가는 재료/성격
      "avoidTags": ["빵", "사과", "우유"],      // 점심 식단표와 겹치면 피하고 싶은 태그
      "steps": ["식빵은 토스터에 2분…", "사과는 얇게 썰어서…"]
    }
  ],

  "lunchMenu": {                              // 🍱 인성이 점심 식단표 연동 자리
    "active": false,                          // 식단표를 받아 채우면 true
    "note": "인성이 점심 식단표 보내주시면 겹치지 않게 아침·저녁을 맞춰 추천해요!",
    "todayLunch": null,                       // 예: "소고기 미역국, 시금치나물, 귤"
    "weekPlan": []                            // 요일별 식단표
  },

  "shopping": [                               // 🛒 장보기 (비어 있으면 친절한 빈 화면)
    { "name": "우유", "emoji": "🥛", "reason": "곧 떨어져요 · 마지막 1팩" }
  ]
}
```

### 규칙 몇 가지

- `category`는 `data.json`에 적힌 이름 그대로 필터 칩이 됩니다. 지금 쓰는 값: `밀키트`, `생선·고기`, `유제품·빵`, `채소·과일`, `아이 맞춤`
- **`expiryDate`가 `null`이면 날짜를 만들지 않습니다.** 냉장은 초록빛 `냉장 보관`, 냉동은 파란빛 `냉동 보관` 배지만 뜨고, 임박 개수에도 들어가지 않아요.
- 날짜가 있는 재료만 D-day가 계산됩니다 — `D-day`·`D-1` 빨간 펄스 · `D-2~3` 주황 · `D-4` 이상 민트 · 지난 날짜 `D+n`
- `meals[].uses`는 재료 `name`과 글자가 같으면 ✅, 없으면 🛒. 긴 상품명은 짧게 줄여 써도 부분 일치로 찾아요. (예: `우유 식빵` → `클래식 우유 식빵 420g`)
- **점심 식단 연동**: `lunchMenu.active`를 `true`로 두고 `todayLunch`에 그날 점심 메뉴를 적으면, 각 메뉴의 `keywords`·`avoidTags`와 겹치는 식단에 `⚠️ 점심과 겹침` 표시가 붙고 목록 뒤로 밀려요. 아침·저녁 추천이 점심과 겹치지 않게 되는 구조예요.

## 배포

`main` 브랜치에 푸시하면 GitHub Pages가 그대로 서빙합니다. 빌드 과정 없음, 상대 경로(`./data.json`)만 사용.

```bash
git add -A && git commit -m "냉장고 업데이트" && git push origin main
```
